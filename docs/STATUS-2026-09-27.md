## What the app is

Secure Total Scan checks the security of anything exposed to the internet.

| Part | Stack | What it does |
| --- | --- | --- |
| Web (`app/`, `components/`, `lib/`) | Next.js 15.5, React 19, Tailwind, TypeScript | Landing page and the free surface scan. `POST /api/scan` takes a URL and an email, fetches the page, its same-origin JS bundles and a set of well-known paths (`/.env`, `/.git/config`, `/phpinfo.php` ...), and grades it A to F across 12 categories (headers, CORS, secrets in bundles, exposed files, HTTPS/HSTS, DOM-XSS sinks and more). |
| Deep-agent backend (`backend/`) | FastAPI, LangGraph, OpenRouter, Trivy | Seven-agent pipeline over logs, a GitHub repo or a Docker Hub image. Reached only through the authenticated proxy `app/api/agent/[...path]`. |
| Data (`migrations/`, `lib/db`) | Neon Postgres | Schema and a forward-only migration runner. No API route writes to it yet. |

Deploys: web on Vercel, backend on Railway (see `vercel.json`, `backend/railway.toml`).

## How to install, build, run and test

```bash
# Web
npm ci
npm run typecheck
npm run lint
npm run build
npm run verify:scanner        # all offline web test suites, including the SSRF suite
npm run dev                   # http://localhost:3000

# Scan something from the command line
npm run scan -- https://example.com
npm run scan -- http://localhost:3000 --allow-loopback   # your own local app only

# Backend
cd backend
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest tests/ -q
uvicorn main:app --reload
```

## End-to-end proof of the core function

Against the production build of this app running locally (`next start -p 3917 -H 127.0.0.1`):

```text
$ npm run scan -- http://127.0.0.1:3917 --allow-loopback
http://127.0.0.1:3917/  grade B  score 80  (282 ms)
findings: 0 critical, 1 high, 0 medium, 0 low, 1 info
  [info    ] Input Validation: Forms present: verify server-side validation
  [high    ] Transport Security (HTTPS/HSTS): Site not served over HTTPS

$ node .verify/scripts/scan-local.js http://127.0.0.1:3917
For safety, internal and private addresses cannot be scanned.

$ node .verify/scripts/scan-local.js http://localtest.me:3917     # public name, resolves to 127.0.0.1
For safety, internal and private addresses cannot be scanned.
```

(One punctuation mark in a finding title is changed to a colon for this document.)

The same app's API refuses internal targets:

```text
POST /api/scan {"url":"http://localhost:3917"}                     -> 422 internal and private addresses cannot be scanned
POST /api/scan {"url":"http://169.254.169.254/latest/meta-data/"}  -> 422 internal and private addresses cannot be scanned
```

`scripts/verify-ssrf.ts` also runs a full `scan()` against a deliberately weak sample app on loopback on every CI run. It gets grade F with 9 findings, including the exposed `.env`, missing headers and a key-shaped string in the JS bundle.

## What is still missing or not verified here

- Deep-agent runs against the live backend were not exercised: they need `OPENROUTER_API_KEY`, `STS_SERVICE_TOKEN` and a Trivy install.
- `/api/scan` needs a durable rate-limit store (Upstash) in production mode and returns 503 without one. That is deliberate fail-closed behaviour, not a bug.
- `next lint` is deprecated and goes away in Next.js 16. Moving to the ESLint CLI is a follow-up.
- 13 open Dependabot PRs, several months old. Not merged here: those are Anthony's calls.
