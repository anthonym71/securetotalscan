## Attacks that failed (the fixes held)

- **Static spellings (web):** decimal `2130706433`, hex `0x7f000001`, octal `0177.0.0.1`, short `127.1`, `0`, `0.0.0.0`, `255.255.255.255`, `[::1]`, `[::ffff:127.0.0.1]`, `[::ffff:7f00:1]`, `[::127.0.0.1]`, NAT64 `[64:ff9b::a9fe:a9fe]`, 6to4 `[2002:a9fe:a9fe::]`, Teredo `[2001::1]`, trailing dots, `.internal`, `[fd00:ec2::254]`, `100.100.100.200`, fullwidth and ideographic-dot digits: all refused. Zone ids are rejected by the URL parser; a zone id in a DNS answer is stripped and classified.
- **Mixed DNS answers:** one private record among public ones is refused in both runtimes.
- **Redirects:** to `file:`, `gopher:`, the metadata IP, an IPv4-mapped IPv6 literal and a decimal IP literal were all refused. A redirect loop stops after 5 hops (6 requests).
- **Backend spellings:** decimal is refused as a bare name; `0x7f.1`, `0177.0.0.1`, `127.1` go through `getaddrinfo` and are checked on the answer (fail closed). No `urlparse`/`httpx` host differential with backslash or `@` tricks.
- **Body cap:** streamed and stopped at 2.5 MB; the abort timer also covers the body read.
- **CLI-only loopback:** `/api/scan` calls `scan(target.toString())` with no guard options; only `scripts/scan-local.ts` sets `allowLoopback`, and it never admits private or link-local.
- **GitHub validation:** Cyrillic and fullwidth lookalikes, `..`, `.git`, `%2e`, `%2f`, `github.com%2f@evil.com`, `github.com.`, extra path segments: refused or reduced to the first two segments.
- **Docker validation:** `..`, a leading `-` in the tag and extra segments are refused; Trivy is called with an argument list.
- **System logs:** off unless `STS_ALLOW_SYSTEM_LOGS` is set; falls back to synthetic logs.

## To reach PASS

1. R2: fail closed on a resolver error or empty answer (web).
2. R1 and R3: pin each connection to the checked address (undici dispatcher `connect.lookup` on the web; a pinned transport in the backend). Add a test with a resolver that answers public for the check and private for the connection.
3. R4 and R5: `trust_env=False`, stream and cap the backend header fetch, and set an overall deadline.

R6 to R8 can follow in a later PR. If the Next.js RCE patch cannot wait for the SSRF rework, split commit `f299028` into its own PR and merge that first.
